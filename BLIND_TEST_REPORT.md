# Blind test

We have not swapped README files with a team outside our ring. Nobody who has never seen HospitalQ has tried this README against a running API, so we cant say they got a response. That part is still open. If the lab clock runs out, it has to happen after class and this file needs an update with what actually happened. We are not going to write that they succeeded when they have not tried.

What we did check on our own machine, which is not the blind test: after seed, `curl.exe http://localhost:5000/api/departments` came back 200 with Dental, General OPD and Pediatrics. `curl.exe http://localhost:5000/api/queue/not-a-real-id` came back 404 with `DEPT_NOT_FOUND`. Login with the seeded receptionist came back 200.

The docs page is `docs/index.html`. It has the six contract routes, with a request shape where the route takes a body and a response shape on all of them. Opening that file does not start the server. The script on the page loads from the Redoc CDN, so the styling needs internet. The route list is already in the file.

Gap we already know about, before anyone else reads it: department ids are generated by Mongo, so a queue URL copied from our sample 404s on a new database. The README says to copy General OPD's `_id` from the departments call first. If someone skips that and pastes our id, that is on the docs, and we should hear about it from the swap rather than guess.
